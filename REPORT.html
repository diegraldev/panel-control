what changed (without changing behaviour)

  • PC agent: CPU from the delta of /proc/stat (previously the average since boot); temperature from sysfs without sensors; IP via ioctl without hostname; T3 Code by scanning /proc/*/comm without pgrep; GPUs via persistent samplers; HTTP/1.1 keep-alive + long-poll for commands.
  • Panel: in-memory state with atomic writes (tmp+rename); HTTP/1.1 + TCP_NODELAY; gzip + ETag for the HTML; asynchronous wake; CORS and Host restrictions; optional token (PANEL_TOKEN); auto-deploy via an ETag Atom feed (no GitHub API limit) that only restarts if server.py changed.
  • Design: same scheme as gotors.dev — black background, white text, lowercase titles and cyan accents on hover/click. No animations.
  • Delays: panel polling 2 s → 1 s; network backoff 1 s → 0.2 s; GPU window 1.5 s → 0.6 s; deploy 30 s → 10 s (free 304s). The publish interval is still configurable (PANEL_INTERVAL).

compatibility

  • Same endpoints: /, /status, /cmd, /cmd/ack, /ack, /estado, /estado_cmd, /version.
  • Same JSON fields and same commands: shutdown, wake, cancelar, t3-open, t3-close.
  • Same state files (status.json, cmd.json, ack.json) and the same user systemd service.
  • GET /cmd still responds immediately; ?wait=N is an optional, backwards-compatible addition.
Measurements: 15 repetitions for collection · 40 s of real runtime for CPU · 25 s with instrumented PATH for forks · 300 requests for latencies · 4 end-to-end command repetitions. Scripts in bench/.
